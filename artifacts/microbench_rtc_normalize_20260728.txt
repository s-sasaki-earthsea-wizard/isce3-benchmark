# RTC _normalizeRtcArea microbenchmark — plain OMP vs Eigen variants
#
# Context: isce-framework/isce3#341. Question under test: would an
# Eigen-expression implementation (idiomatic, since isce3::core::Matrix
# derives from Eigen::Array) beat the plain-OMP fix filed in the issue?
#
# Bench: poc/rtc_normalize_microbench/ @ isce3-benchmark branch
# feat/microbench-rtc-normalize. Container-side, conda GCC 13.3,
# -O2 -g -DNDEBUG (same toolchain/flags as the isce3 RelWithDebInfo
# build used for the #341 measurements). Inputs: deterministic
# hash-initialized arrays, 5% exact zeros in the denominator.
#
# Answer: no. v1 (plain OMP, the #341 fix) and v2 (OMP + per-row Eigen
# select) are indistinguishable — both saturate memory bandwidth
# (7.44 GB / 0.127 s = 58.6 GB/s vs 57.4 GB/s parallel-memcpy roof).
# Vectorization cannot help a bandwidth-bound pass. A naive whole-array
# Eigen rewrite (v3) would be a 7x regression vs the fix because Eigen
# does not thread coefficient-wise expressions — though still 38x
# faster than develop's dynamic+atomic loop (v0).
#
# All four variants produce bit-identical output (asserted vs v0).
